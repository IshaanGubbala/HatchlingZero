# HZ-0H Phase F Gap Closure

Date: 2026-08-14

This records the implementation that closes the remaining measurement
infrastructure gaps without overstating results that require the RTX3060
checkpoint artifacts.

## Completed in the repository

- `scripts/hz0h_phase_f_domain_ce.py` evaluates code and math/reasoning
  byte-packed validation streams with the exact matched BDH, VB, and RoPE
  Transformer configurations. It emits CE, perplexity, token count,
  throughput, peak memory, finite status, and checkpoint provenance as JSON.
- `reference/hz0h_bdh_torch.py` and `reference/hz0h_bdh_vb_torch.py` now have
  bounded chunked-prefill helpers. Absolute positions and recurrent state are
  carried across every chunk, including uneven final chunks.
- `scripts/hz0h_inference_benchmark.py` uses the bounded helpers for BDH,
  VB, and base+delta INT8 streaming prefill. `--prefill-chunk-length` defaults
  to 1024, so long-context streaming and BDH/VB prefill measurements do not
  call the quadratic plain-forward attention path. With
  `--skip-naive-replay`, the known non-streaming BDH KV-cache WDDM stall is
  recorded explicitly and skipped. The RTX3060 rerun reproduced that stall at
  context 8192 after chunked prefill, so the effective safe skip threshold is
  8192, not 16384. This does not affect the bounded streaming-state path.
- `reference/hz0h_energy.py` provides a clearly labelled `nvidia-smi
  power.draw` polling sampler. Exact BDH, VB, and Transformer training runners
  now include mean watts, integrated joules, joules/token, sample count, and
  sampler method in their reports. Missing `nvidia-smi` produces null energy
  fields rather than a false zero.

## Verified locally

The focused regression suite passes 7/7. It proves exact BDH and VB logits and
recurrent states match one-call streaming for uneven chunk boundaries, and
checks safe unavailable-energy behavior. All edited Python modules compile and
the diff has no whitespace errors.

## Required GPU closure commands

Run on the RTX3060 host after the three matched checkpoints are available:

```bash
python scripts/hz0h_phase_f_domain_ce.py \
  --bdh-checkpoint outputs/hz0h_phase6_depth_curriculum/seed7/bdh_depth_curriculum_stage2_checkpoint.pt \
  --bdh-vb-checkpoint outputs/hz0h_phase6_vb_depth_curriculum/seed7/bdh_vb_depth_curriculum_stage2_checkpoint.pt \
  --transformer-checkpoint outputs/hz0h_phase_f_matched_transformer/seed7/torch_stage2_checkpoint.pt \
  --code-data data/packed/external/code_validation_byte.jsonl \
  --math-data data/packed/external/mathematical_and_structured_validation_byte.jsonl \
  --prefill-chunk-length 256 \
  --dtype bfloat16 --device cuda --batch-size 1 \
  --out outputs/hz0h_phase_f/domain_ce.json

python scripts/hz0h_inference_benchmark.py \
  --device cuda --dtype bfloat16 \
  --context-lengths 8192,16384,32768 \
  --skip-naive-replay --prefill-chunk-length 1024 \
  --output outputs/hz0h_phase_f/chunked_long_context.json
```

The first command closes code/math-reasoning CE only when the result JSON is
produced from token IDs verified in `[0,255]`. The second closes the
beyond-8192 streaming and bounded-prefill gate when 16K and 32K complete with
finite outputs and stable peak-memory bands. Training
reports generated by the three runners close the training-energy gate when
`energy_available=true`; polling energy remains an estimate, not a hardware
energy-counter reading.

## Final GPU closure status

The Windows RTX3060 closure completed all four measurement stages with a
stale-process audit before every stage and one GPU job at a time. The corrected
byte-packed domain files passed with finite results for all three arms:

```text
                 code CE       math/reasoning CE
exact BDH         1.933994      2.661655
VB D/4            1.929817      2.682800
Transformer       1.950970      2.843565
```

Bounded chunked prefill completed at 8192, 16384, and 32768 tokens. Streaming
decode stayed approximately 190.2 -> 192.6 -> 192.5 tok/s for exact BDH,
while Transformer KV-cache decode fell approximately 158.1 -> 103.4 -> 57.7
tok/s. The ordinary BDH KV-cache measurement is intentionally unavailable at
all three lengths because of the reproducible WDDM stall; this is a labeled
hardware/path limitation, not a silently missing result.

All three 25M-token training reruns completed with `energy_available=true`:
exact BDH 0.015868 J/token, VB D/4 0.015798 J/token, and Transformer 0.002551
J/token. These values come from sampled `nvidia-smi power.draw` integration.
